# 整体项目计划

更新：2026-09-26｜当前版本：0.2.0（`f7d6f4e`）

## 1. 交付目标

围绕“感知目录 → 批量建议 → 确认整理 → 清理空目录 → 可撤销”形成可重复验证的文件整理流程。功能范围见[需求文档](requirements.md)，实现见[架构文档](architecture.md)。

## 2. 阶段与成果

| 阶段 | 状态 | 成果 / 完成门槛 |
| --- | --- | --- |
| M1：整理 MVP | 已实现 | Java 17 / IDEA 启动、根目录感知、递归扫描、AI 建议、确认移动、允许新建分类目录 |
| M2：效率与恢复 | 已实现，基础验证通过 | 深度可配的目录树、批量并发、阶段日志、空目录清理、最近一次撤销 |
| M3：工程交付 | 已完成 | Maven Wrapper、5 项自动化测试、隔离手动样例、GitHub CI、配置与产物排除、四份项目文档 |
| M4：可靠性加固 | 下一阶段，待实施 | 完成下表 P0 项及回归测试 |
| M5：性能与服务兼容 | 待实施 | 完成批次规模对比、异常回退测试，给出实测配置建议 |
| M6：内容理解 | 待确认范围 | 根据真实分类误差决定是否加入 PDF / Office 文本提取、图片分析 |

“已实现”表示功能存在，不代表异常边界全部覆盖。现有验证为 5 项自动化测试及 4 文件真实 AI 整理 / 撤销；尚未完成约 184 文件的完整验证。

## 3. 下一阶段工作顺序

| 优先级 | 工作项 | 验收门槛 |
| --- | --- | --- |
| P0 | 路径与响应校验 | 符号链接不能绕过根目录边界；无效 JSON / 错配建议不执行；明确隐藏子目录规则 |
| P0 | 移动与撤销异常处理 | 覆盖未确认、同名冲突、部分失败、历史损坏和修改后的文件；不覆盖、不丢失，剩余项可追踪 |
| P1 | 批量效率与异常回退 | 以 10 / 50 / 184 文件对比逐文件与批量模式，记录耗时、请求数、回退数、成功率 |
| P1 | 深层目录上下文 | 验证深于展示深度的合理目的地仍能进入 AI 上下文，同时控制请求体积 |
| P2 | 内容分析 | 先用误分类样例证明元数据不足，再选择一种文件类型扩展并验证收益 |

## 4. 验证与发布约定

1. 按 P0 → P1 → P2 推进；未确认的功能扩展不提前开发，暂不承诺日期。
2. 缺陷先建立可复现用例，再修复并回归；执行方式见[测试文档](testing.md)。
3. 发布前通过 `clean verify`，并在 `manual-test` 完成一次真实 AI 建议、确认移动和撤销，记录结果及耗时。
4. Git 仅提交源码、文档和可重复样例；密钥、IDE 配置、构建产物及运行历史保持本地。

持续监听、GUI、多次历史撤销暂缓。当前批量回退可能放大等待时间，第三方响应存在波动，历史恢复不具备整批事务保证；后续验证应围绕这些已知限制展开。
